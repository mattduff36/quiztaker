# Course player knowledge

Vitriol keeps reusable player knowledge separately from course answers and measured execution strategies. Read and quiz proposals observe a bounded list of DOM markers; a family match is an inference, never proof of an exact edition/version. The first supported researched family is dominKnow. Claro and Flow share authoring patterns, so the current recognizer does not distinguish them.

The hosted store reuses user-owned `strategies` rows with capability `player-knowledge`, version 1, and family fingerprint. Evidence records documentation findings with source URLs/research date, observed markers, a count of distinct attempts, last-seen dates and the last 32 job outcomes. Recent attempt identity is bounded to 64 entries; durable attempt events deduplicate observations and outcome replays beyond those display bounds. This is not a promoted executable strategy, and documentation cannot change the action whitelist or prove course completion.

Each proposal receives a bounded navigation context marked as untrusted facts. It contains no answer key or executable code. It helps the learner look for observed controls, including flip cards, reveal panels and resources; it cannot supply current target IDs. Original course material and operator instructions retain their separate roles.

## Research and growth

Initial dominKnow findings were researched on 3 November 2026 from official sources:

- [Authoring features](https://dominknow.com/features): authors can add tabs, accordions, cards, panels, lightboxes and configure navigation/player experiences.
- [Authoring modes](https://dominknow.com/elearning-authoring-tools): Flow is responsive; Claro uses fixed layouts.
- [Flip-card job aid](https://community.dominknow.com/downloadJobAid?id=d1e47b9b&revisionId=05e73264-d40e-49b0-ba9f-2e217b43092b): front/back card content is configured separately and previewed for learners.

On the first recognized encounter and after 30 days, Vitriol checks the two fixed official HTML URLs. Requests reject redirects, have a three-second deadline and a 256 KB body limit. They transmit no course content, credentials or user query. Failures back off for a day. The PDF is cited but not repeatedly downloaded. Checks store availability/hash/date only: they do not silently claim to have researched new meanings or refresh the reviewed-findings date.

Unknown players and observed failures/no-progress runs create one open `player-research` review per user/player. A reviewing agent inspects evidence, researches official sources, adds bounded findings to `PLAYER_PROFILES` with source/date and extends marker recognition where justified. This initial version queues open-ended research; it does not pretend that arbitrary web search is supported by every configured model provider. A later feature can add a genuine research adapter without changing this evidence contract.

The Learning page shows documentation and runtime evidence separately. Successful outcomes are recorded only when the existing run verifier confirms them. Neither an article nor an observation automatically promotes a strategy. Database/document-check failures are nonessential and do not block course work. Normal existing strategy promotion/regression rules remain unchanged.
